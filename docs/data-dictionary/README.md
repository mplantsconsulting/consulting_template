# data-dictionary — 変数定義・データ形状

## 目的

受領データを分析するための**変数定義とデータの形状**を記録する。
加えて、**指標の定義を1箇所に固定する**（後述の定義台帳）。

## 置くもの

- データの定義（列名・型・NULL率・ユニーク数・取りうる値）
- 最低限の基本統計量（詳細な分析は [analysis/](../analysis/)）
- データ集計上の注意事項
- **指標の定義台帳**（`metric_<指標名>.md`）

## 置かないもの

- 詳細な分析内容や結果 → [analysis/](../analysis/)
- 施策や分析計画に関する議論 → [ideas/](../ideas/) [analysis/](../analysis/)
- データの出所・抽出条件 → [business/ref_data_inventory.md](../business/ref_data_inventory.md) が正
- **個人・個体を特定しうる値そのもの**（氏名・住所・電話番号・メールアドレス・個別の識別番号等）。
  **列の存在・型・NULL率は記載してよいが、値の例示は行わない。**

## 命名規則

```
<データソース名>.md      データソース1つにつき1ファイル
metric_<指標名>.md       指標の定義台帳
```

雛形: [_TEMPLATE_source.md](_TEMPLATE_source.md) / [_TEMPLATE_metric.md](_TEMPLATE_metric.md)

## データソース間の結合キー

<!-- 案件開始時に図にする。「全ソース共通のキーがあるか」は早い段階で確認する -->

```
（データソースA） ──〈キー〉──→ （データソースB）
```

**結合は「列が存在する」ことと「実際に一致する」ことを分けて記録する。**

| 結合 | キー | 検証済みか | 一致率 |
|---|---|---|---|
| A ↔ B | | `列の存在のみ確認` / `一致率を実測` | |

- 実測していない結合を前提に分析を組まない。桁数・先頭ゼロ・表記ゆれで一致しないことが多い。
- 全ソース共通で使えるキーが存在しない場合、**必要な範囲だけ結合するのが安全**である。

## 読み込み方法・全数統計の再現

生データの読み込み（文字コード・ヘッダー欠落・列名付与）は [src/](../../src/) に実装する。
`uv run python scripts/prepare_processed_data.py` で `data/processed/*.parquet` に変換する運用を推奨。

**サンプルに基づく統計値は、そのことを明記する。**
処理速度を優先して先頭N行のサンプルで出した NULL率・ユニーク数は暫定値である。
全数での確定値が必要な分析では、都度計算する。

## 指標の定義台帳（最重要）

> **同じ語で、分母・分析単位・測っている概念が違う指標が流通していないか。**

これは案件の早い段階で必ず確認する。**この確認を飛ばすと、
全員が正しい計算をして、全員が違う結論を出す。**

「未収率」「解約率」「稼働率」「単価」のような**日常的に使われる語ほど危険**である。
社内・クライアント双方で定義が固まっていないことが多い。

### 台帳を作るべきサイン

- 同じ語について、複数の資料で違う数値が出ている
- 「分母は何ですか」に即答できない
- 「件数ベース」「金額ベース」「顧客ベース」が混在している
- 順位（どのセグメントが悪いか）が資料によって違う

### 台帳に書くこと

[_TEMPLATE_metric.md](_TEMPLATE_metric.md) を使う。要点は以下。

1. **指標の一覧** — 指標名／分母／分子／分析単位／実測値／出所
2. **使い分け** — どの問いにどの指標を使うか。**使ってはいけない指標も書く**
3. **順位の逆転** — 指標によってセグメントの順位が入れ替わるなら、その対比表
4. **既存の食い違いの説明** — 過去資料の数値がどの指標だったのか

**これは分析ではなく前処理に見えるが、案件で最も価値が高い作業のひとつになりうる。**

## 運用ルール

1. **個人・個体を特定しうる値を書かない。** 列の存在・型・NULL率までにとどめる。
2. **サンプル値か全数値かを明記する。** 暫定値を確定値として扱わない。
3. **「不明」を「不明」と書く。** 列の意味が分からない場合、推測で埋めず [client-qa/](../client-qa/) に回す。
4. **定義を変えたら、影響する分析を洗い出す。** 定義の変更は過去の分析結果の意味を変える。
5. 新規作成・更新したら [INDEX.md](../INDEX.md) に登録する。
