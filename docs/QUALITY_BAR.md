# QUALITY_BAR — 成果物の合格ライン

**成果物を出す前に、自分で必ず答える。1つでも答えられなければ出さない。**

---

## 提出前の4問

| # | 問い | 何を防ぐか |
|---|---|---|
| 1 | **出所** — この数字はどこから来たか？ スクリプトのどの処理まで辿れるか？ | 出所不明の数値の独り歩き |
| 2 | **前提** — 何を前提にしているか？ それが崩れたら結論はどう変わるか？ | 前提を共有していない相手に誤解されること |
| 3 | **判断** — 相手はこれを見て何を判断できるようになるか？ | 「分析しました」で終わること |
| 4 | **反証** — 反対されたらどう答えるか？「言えないこと」を書いたか？ | 質疑での崩壊 |

**この4問はペアで相互チェックする。** 自己申告では機能しない。

## 「学校の課題」と「コンサルティング」は別のゲームである

評価軸が違う。ここを取り違えると、努力の方向がずれる。

| | 学校の課題 | コンサルティング |
|---|---|---|
| 問い | 与えられる | **自分で立てる。依頼文は問いではない** |
| 正解 | 存在する | 存在しない。あるのは意思決定と、その根拠 |
| 評価者 | 採点者（前提を共有している） | クライアント（**前提を共有していない**） |
| 良い成果物 | 網羅的・精緻 | **判断できる・追跡できる・反証に耐える** |
| 「分からない」 | 減点 | **明記すれば加点**（次の確認事項になる） |
| 手法の高度さ | 評価される | **評価されない。問いに従属する** |
| 終わり | 提出したら終わり | **相手が動いたら終わり** |

### 言い切っておくこと

- **「分析しました」は成果ではない。** 「◯◯を判断できるようになった」が成果。
- **問いに答えない高度な手法は0点、問いに答える単純集計は満点。**
- **判断が変わらない精度は過剰。** そこに使った時間は損失である。
- **棄却は成果。** 「効果が見込めないと確認できた」は資料に載せる価値のある結果。
- **前処理に見える作業が、最も価値が高いことがある。** 指標の定義を1つに固定する作業はその典型。

## ステータスごとの参照可否

読み手が「参照していいか」を自分で判断できるように、**ファイル冒頭にステータスを書く。**

| 置き場所 | 参照してよいステータス | 資料へ転記してよいか |
|---|---|---|
| [analysis/](analysis/) | `完了` | `完了` のみ |
| [strategy/](strategy/) | `確定` | 前提を併記すれば可 |
| [business/](business/) | `【仮説・未確認】` が付いていない記述 | 一次資料に基づくもののみ |
| [cases/](cases/) | 出典URLがあるもの | 「他社に事例がある」までは可。因果は不可 |
| [ideas/](ideas/) | `検討中` 以上 | 効果は条件付きで記述する場合のみ |
| [analysis/_archive/](analysis/_archive/) | 参照は可 | **転記は不可** |

## 提出物のチェックリスト

[presentations/](presentations/) に置く前に、以下を確認する。

- [ ] `sources.md` があり、**資料上のすべての数値**がファイル名と該当箇所まで書かれている
- [ ] 載せた数値の出所分析がすべて `完了`（`検証中` が混ざっていない）
- [ ] 事実記述に `【仮説・未確認】` の内容が混ざっていない
- [ ] 推定値・シミュレーション値には、スライド上に前提が明記されている
- [ ] 「言えないこと」「確認できなかったこと」が資料またはトークスクリプトに入っている
- [ ] 棄却した仮説が隠されていない
- [ ] 個人を特定しうる値（氏名・住所・電話番号・個別の識別番号など）が含まれていない
- [ ] 見出しが「結果を述べる文」になっている（解釈の言い切りになっていない）
- [ ] 想定質問への回答が用意されている（特に母数・カバー率・抽出条件）

## レビューのタイミング

**1時間の説明で行動は変わらない。仕組み側で担保する。**

| いつ | 何を |
|---|---|
| 案件の初日 | この雛形の使用を必須にする |
| 分析1本目 | **結果を見る前に**、判定基準まで書いた時点でレビューする |
| 提出前 | 「提出前の4問」をペアで相互チェックする |
| 週1 | [INDEX.md](INDEX.md) を読み合わせ、ステータスの棚卸しをする |

**特に2番目が重要。**
「判定基準を結果を見てから変えない」は自己申告では守られない。
**結果が出る前にレビューが入る運用にして初めて機能する。**
