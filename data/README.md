# data — データ置き場（Git管理外）

**このフォルダの中身はコミットしない。**
顧客情報を含みうるため、`.gitignore` で `/data/**` を除外している（この README のみ例外）。
分析ファイルからは**「パスと取得方法」だけを参照する。**

## 構成

| パス | 中身 | ルール |
|---|---|---|
| `raw/` | クライアントから受領した生データ | **不変。** 中身を書き換えない。受領時のファイル名・フォルダ名を変えない |
| `interim/` | 前処理の途中経過（結合前、クレンジング中など） | 再生成できるものだけ。**消えても困らない状態を保つ** |
| `processed/` | 分析の入力として確定させたデータ | 生成スクリプトを [scripts/](../scripts/) に残し、**手作業で作らない** |

`raw/` のフォルダ名に含まれる日付は**受領日または抽出日**であり、**データの対象期間ではない。**

## 新しいデータを受領したら

1. `raw/` に**受領時のまま**置く（解凍のみ可）。
2. 出所・抽出者・抽出日・抽出条件を [docs/business/ref_data_inventory.md](../docs/business/ref_data_inventory.md) に記録する。
3. 列定義・データ形状を [docs/data-dictionary/](../docs/data-dictionary/) に記録する。
4. **抽出条件が不明な場合は「不明」と書く。推測で埋めない。**
   **母数が不明なデータで比率を出すと、その比率は意味を持たない。**

## 取り扱いの注意

- **`docs/` 配下や Git の管理対象に、個人・個体を特定しうる値を出さない。**
  氏名・住所・電話番号・メールアドレス・個別の識別番号を列に持つファイルは、
  集計途中であっても `docs/` に置かない。
- 受領データの保管場所・保持期間・削除の取り扱いは、案件の契約条件に従う。
  案件終了時の削除が必要な場合は、その旨を `ref_data_inventory.md` に記録する。
- ヘッダー行がないファイル等、読み込みに注意が必要なものは
  **列名の取得元を `ref_data_inventory.md` に必ず記録する。**
  （誤ってデータ1行目をヘッダーとして読み込むと、個人情報が列名として展開されることがある。）
