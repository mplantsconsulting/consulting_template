提出物を `docs/QUALITY_BAR.md` のチェックリストに照らして点検してください。対象: $ARGUMENTS

（対象の指定がない場合は、`docs/presentations/` の最新フォルダ）

## 1. 提出前の4問

資料の内容から、以下に**答えられるかどうか**を判定する。答えられない箇所を具体的に指摘する。

| # | 問い | 判定 |
|---|---|---|
| 1 | **出所** — この数字はどこから来たか。スクリプトまで辿れるか | |
| 2 | **前提** — 何を前提にしているか。崩れたら結論はどう変わるか | |
| 3 | **判断** — 相手はこれを見て何を判断できるようになるか | |
| 4 | **反証** — 反対されたらどう答えるか。「言えないこと」を書いたか | |

## 2. 機械的に確認する項目

### sources.md の完全性

- [ ] `sources.md` が存在する
- [ ] **資料上のすべての数値**が `sources.md` にある（資料側を読んで数値を列挙し、突き合わせる）
- [ ] 各数値の出所ファイルが実在する
- [ ] 出所分析のステータスが**すべて `完了`**（`検証中` `計画確定` が混ざっていないか）
- [ ] `_archive/` の分析から**転記**されていないか（参照は可、転記は不可）

### 事実記述

- [ ] `【仮説・未確認】` が付いた記述が資料に混ざっていないか
- [ ] **三次資料**（社内の手順書・過去の成果物・既存コード）だけを根拠にした事実記述がないか
- [ ] 「規程にある」を「実際に行われている」として書いていないか

### 施策

- [ ] 記載された施策の `docs/ideas/` のステータスが `検討中` 以上
- [ ] 効果が断定になっていないか（条件付きで書かれているか）
- [ ] 根拠のない効果見込みの数値がないか

### 推定値

- [ ] 推定値・シミュレーション値に、**スライド上に前提が明記**されているか
- [ ] 実測値と推定値が同じ書式で並んでいないか

### 留保と反証

- [ ] 「言えないこと」「確認できなかったこと」が資料または口頭の台本に入っているか
- [ ] **棄却した仮説が隠されていないか**（サマリに「効果が見込めないと確認できたもの」があるか）
- [ ] 口頭で伝える留保が一覧化され、どのページで言うか決まっているか
- [ ] 想定質問への回答が用意されているか（**特に母数・カバー率・抽出条件**）

### 形式と安全性

- [ ] 見出しが「結果を述べる文」になっているか（解釈の言い切りになっていないか）
- [ ] **個人・個体を特定しうる値**（氏名・住所・電話番号・個別の識別番号）が含まれていないか
- [ ] 分析対象範囲が資料に明記されているか

## 出力形式

```markdown
## 判定: 提出可 / 要修正（重大N件）

## 重大な問題（修正しないと提出できない）
| # | 問題 | 該当箇所 | どう直すか |
|---|---|---|---|

## 修正が望ましい点

## 提出前の4問への回答状況
| # | 判定 | 答えられない箇所 |
|---|---|---|

## 口頭で必ず伝えるべき留保（台本化の確認）
| # | 留保 | 資料のどこで言うか |
|---|---|---|
```

**修正は勝手に行わず、報告してから確認を取ってください。**
このチェックは機械的な確認であり、**ペアでの相互チェックの代替にはなりません**（`docs/QUALITY_BAR.md`）。
