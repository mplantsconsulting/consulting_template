---
description: 直前の結論・成果物に反証を当てる
---

以下について、**反証役として**指摘してください。対象: $ARGUMENTS

（対象の指定がない場合は、この会話で直前に出した結論・成果物）

## あなたの役割

**このコマンドでは、賛成しないこと。**
結論を補強する材料ではなく、**それを崩す材料だけ**を挙げてください。
「概ね妥当ですが」という前置きを付けないでください。

## 指摘してほしいこと

1. **前提が崩れるケース**
   - この結論が依拠している前提を列挙し、それぞれが崩れる条件を挙げる
   - 特に「母数」「抽出条件」「対象期間」の前提

2. **別の説明**
   - 同じ数値・事実から導ける、**異なる解釈**を挙げる
   - 交絡（別の要因で説明できないか）、逆の因果、選択バイアス

3. **データが語っていないこと**
   - 対照群があるか。ないなら効果を主張できるか
   - 観測できていない範囲（脱落・未記録・カバー率）
   - 「差がある」と言うために必要な情報が揃っているか

4. **業務側の反論**
   - 現場・クライアントから出る想定反論
   - 「それはもうやっている」「その前提は実態と違う」と言われる可能性

5. **数値の追跡可能性**
   - 出所が辿れない数値、`検証中` の混入、三次資料に依拠した事実記述

6. **言えていないことの言い漏れ**
   - 「この分析で言えないこと」に書くべきなのに書かれていない項目

## 出力形式

```markdown
## この結論が崩れる条件

| # | 崩れる条件 | 崩れたらどうなるか | 潰し方 |
|---|---|---|---|
| 1 | | | → analysis / → client-qa / → 潰せない |

## 同じ事実から導ける別の解釈

| # | 別の解釈 | どちらが正しいかを分ける情報 | 手元にあるか |
|---|---|---|---|

## 想定される反論（クライアント側）

| # | 反論 | 現時点で答えられるか |
|---|---|---|

## 「言えないこと」への追記が必要な項目

## 潰せない（データでは決着しない）もの
→ `docs/client-qa/` の照会項目にすべきもの
```

## 補足

- **反証できなかった点は、その旨を書いてください。** 「この点は否定材料が見つからなかった」も有益な情報です。
- 施策の採否は判断しないでください。
- 反証のために推測を事実として書かないでください（反証の質も同じ基準で評価されます）。
