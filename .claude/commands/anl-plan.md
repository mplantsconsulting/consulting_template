`docs/analysis/` に新しい分析の**計画**を起案してください。テーマ: $ARGUMENTS

## 手順

1. 担当者ディレクトリ `docs/analysis/<担当者名>/` を確認し、**そのディレクトリ内で未使用の連番**を採番する
   （他の担当者の採番とは独立でよい。採番済みの番号は再利用しない。**担当者名が不明な場合は確認する。推測で決めない**）
2. `docs/analysis/_TEMPLATE.md` を担当者ディレクトリにコピーして `ANL-NNN_<分析テーマ>.md` を作る
   （担当者ディレクトリが存在しなければ作成する）
3. **【計画】の欄だけを埋める。** 【結果】側は見出しだけ残して空にする
4. 埋める際、以下を必ず守る
   - **問い**は「〜は〜か」の1文。「〜を分析する」は問いではない
   - **仮説**は作業仮説として書く。なければ「なし（探索的）」
   - **データソース**は `docs/business/ref_data_inventory.md` と
     `docs/data-dictionary/` を参照し、実在するファイル名で書く。
     **不明な項目は「不明」と書く。推測で埋めない**
   - **前提・制約**に「この前提が崩れると結論が変わる点」を必ず書く
   - **手法**は使う列・結合キー・集計単位まで書く
   - **判定基準**は「何がどう出たら何が言えるのか」を結果を見る前に書き切る。
     定量的に線を引けない場合は「線を引けない（記述に留める）」と明記する
   - **未確認事項**を空欄にしない（なければ「なし（確認済み）」）
5. 使う指標が `docs/data-dictionary/` の定義台帳にあるか確認する。
   **同じ語で分母の違う指標が流通していないかを確認し、疑わしければ指摘する**
6. 判定基準まで書けたらステータスを `計画確定` にする
7. `docs/INDEX.md` に登録する

## 最後に報告すること

- 採番したID、問い、判定基準の要点
- **判定基準が書けなかった項目**があれば、その理由と次のアクション
  （データがない → `client-qa/` / 業務が不明 → `business/` / 問いが大きい → 分割）
- **集計は実行しない。** 計画のレビューを受ける前に集計に進まないこと

> この時点でレビューを受けてから集計に進みます（`docs/QUALITY_BAR.md`）。
