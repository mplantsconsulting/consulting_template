リポジトリ内の未確認事項を集約し、先方への照会文を `docs/client-qa/` に作ってください。範囲: $ARGUMENTS

## 手順

### 1. 未確認事項を集める

以下をすべて読み、未確認・未決着の項目を洗い出す。

| 場所 | 拾う対象 |
|---|---|
| `docs/analysis/*.md` | 「未確認事項」「この分析で言えないこと」の各節 |
| `docs/strategy/*.md` | 「空欄の一覧」「未確認事項」の各節 |
| `docs/data-dictionary/*.md` | 「分かっていないこと」「集計上の注意事項」の要確認項目 |
| `docs/business/*.md` | `【仮説・未確認】` タグが付いた記述 |
| `docs/business/ref_data_inventory.md` | 抽出条件が「不明」のデータ、未受領データ |
| `docs/ideas/*.md` | 「未確認事項」「前提条件」の `未確認` 項目 |

### 2. 仕分ける

| 種別 | どうするか |
|---|---|
| **質問すれば答えられる** | 照会文の質問にする |
| **調査・作業が必要** | 質問にせず「**データ追加提供のお願い**」に分離する |
| **自分で潰せる** | 質問にしない。→ どの分析・どの資料で潰せるかを報告する |

### 3. 重複を統合する

複数の分析から同じ論点が出ている場合は1問にまとめ、**どの分析が依存しているか**を記録する。

### 4. 照会文を作る

`docs/client-qa/_TEMPLATE.md` を使い、`QA-NNN_<内容>_<回次>.md` を作る。

**設計の制約（回答負荷を最優先で下げる）**

- **1問1論点。** 長い前置きを付けない
- **選択肢へのチェック、または単語1つで答えられる形にする**
- **1回の照会は20問を超えない。** 超える場合は優先度で切る
- **各質問に「☐ 分からない／担当が別」の選択肢を必ず置く**
  （推測で埋められるのが最も困るため）
- **「まずこの5問」を先頭に置く。** これだけで主要な詰まりが解ける問いを選ぶ
- 各質問に「なぜ聞くのか」を1〜2行で添える

### 5. 社内メモを付ける

末尾に「社内メモ（先方には送らない）」として、
**回答が来たときの反映先**と、**回答待ちで塞がっている分析**の対応表を作る。

## 最後に報告すること

- 作成したファイル、質問数、データ依頼件数
- **「まずこの5問」に選んだ理由**
- 質問にしなかった項目（自分で潰せるもの）とその潰し方
- 20問に収めるために落とした項目（あれば）
- `docs/INDEX.md` への登録
