# external-research — 外部事例を調査する

## いつ使うか

- 施策の検討材料を集めるとき（WORKFLOW の Step 1 と並行）
- 「他社はどうしているか」を聞かれたとき
- 既存のソリューション（SaaS・ベンダー）で済むかを確認するとき

## 絶対の制約

1. **出典URLは実在するものだけを書く。記憶からの捏造は禁止。**
   検索して実際に到達したページのみを出典とする。
2. **確認できなかったことは「情報不足」「非公開」と明記する。**
   **埋め合わせで一般論を書かない。**
3. **調べていないことを、調べた風に書かない。**
   検索手段の限界（アクセスできなかった、日本語情報がなかった等）も記録する。

**ここに置く情報はクライアントの事実ではない。**
[ideas/](../../../docs/ideas/) の根拠として引用してよいのは
「〇〇社ではこういう施策が存在する（出典あり）」という**事実そのものまで**であり、
**「だからクライアントでも効果が出る」という因果は立証されない。**

## 数値の種別を必ず区別する

| 種別 | 扱い |
|---|---|
| 独立検証がある学術論文・規制当局資料 | 最も強い |
| 企業のIR・プレスリリース | 一次情報だが**自社発表** |
| ベンダー（SaaS提供企業）公表の導入効果 | **マーケティング目的の可能性がある自己申告値** |

**各事例にどれに当たるかを明記する。** ベンダー公表値を実測値と同列に並べない。

## 手順

1. **調査対象範囲を先に決める。** 業種・地域・企業規模・年代。
   **範囲外は「調べていない」と明記する。**
2. **調査の軸を3つ程度に分ける。**
   - 同業他社（類似のビジネスモデル・業務構造）
   - 他業種（構造が似ていれば業種は問わない）
   - ソリューション（実在するプロダクト・SaaS）
3. **検索し、実際に到達したページのみを記録する。**
4. **各事例に、施策概要・目的背景・効果・数値の種別・出典URL・アクセス日を付ける。**
   効果の数値がない事例も「効果の公表なし」と書いて載せる。
5. **反例・限界が報告されている事例を別立てで探す。**
   「効果があった」事例だけを集めない。
   「見かけ上の改善に留まった」「規制対応が後手に回った」も**同格の判断材料**である。
6. **確認できなかった項目を一覧にする。** 何を調べようとして、なぜ分からなかったか。
7. **示唆は「〜の可能性がある」「検討材料になりうる」の範囲に留める。**
   クライアントへの適用可否は判断しない。

## 出力形式

ファイルは [docs/cases/_TEMPLATE.md](../../../docs/cases/_TEMPLATE.md) に沿って書く。

調査結果を報告する際は、以下の順で出す。

```markdown
## 調査範囲
- 対象: 〈業種・地域・企業規模・年代〉
- 調べていない範囲: 〈範囲外を明示する〉
- 調査手段: 〈何で調べ、何で調べなかったか〉

## 事例一覧
| # | 企業名 | 施策概要 | 効果（数値） | 数値の種別 | 出典URL | アクセス日 |
|---|---|---|---|---|---|---|
| 1 | | | 〈公表なしなら「公表なし」〉 | 学術・当局 / 自社IR / **ベンダー自己申告** | | |

## 反例・限界が報告されている事例
| # | 企業名 | 何が起きたか | 出典URL |
|---|---|---|---|
〈探した上でなければ「探したが見つからなかった」と書く〉

## 確認できなかった項目
| # | 調べようとしたこと | なぜ分からなかったか |
|---|---|---|
| 1 | | 非公開 / 情報不足 / 検索手段の限界 |

## 示唆（参考情報。採否はここで判断しない）
〈「〜の可能性がある」「検討材料になりうる」の範囲に留める〉

## この調査で言えないこと
〈「他社に事例がある」までは言えるが、自社で効果が出るとは言えない旨を明記〉
```

## 品質基準

- **すべての出典URLが実際に到達したページである**
- **数値の種別が各事例に明記されている**
- **反例・限界の節が空でない**（探した上でなければ「探したが見つからなかった」と書く）
- **「確認できなかった項目」が空でない**
- **示唆が断定になっていない**
- 調査範囲外を明記している
- クライアントへの適用可否を判断していない
