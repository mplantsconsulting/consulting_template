# deliverable-narrative — 提示資料の構成を作る

## いつ使うか

- 報告会・提案の資料を作るとき（WORKFLOW の Step 6）
- **本体スライドを作る前。** 構成が固まる前に作図しない

## 前提

資料は「分析の報告」ではなく **「相手が判断するための道具」** である。

**掲載の条件を先に確認する。** 満たさないものは資料に載せない。

| 載せるもの | 条件 |
|---|---|
| 数値 | [analysis/](../../../docs/analysis/) のステータスが `完了` |
| 事実記述 | [business/](../../../docs/business/) で `【仮説・未確認】` が外れている |
| 施策 | [ideas/](../../../docs/ideas/) のステータスが `検討中` 以上 |

**`検証中` の数値を資料に転記しない。暫定値は必ず独り歩きする。**

## 設計の核: スライドと口頭を分ける

| どこに | 何を |
|---|---|
| **スライド** | 分析の内容と結果 |
| **口頭** | 仮説・解釈・示唆・留保・判断のお願い |

構成段階から各ページを `スライドに載せる` / `口頭で補足` の2段に分けて書く。
この切り分けをすると、スライドから解釈が消えて事実だけが残る。
**質疑で崩れるのは、たいていスライドに書いた解釈のほうである。**

## 手順

1. **この資料で動かしたい意思決定を1文で書く。**
   ここが書けないなら構成は決まらない。
2. **依頼元の項目（聞かれていること）を列挙し、ページに対応づける。**
   聞かれていないことを足す前に、聞かれたことに全部答える。
3. **ページ構成の一覧を作る。** 本編は絞り、網羅性は Appendix に落とす。
4. **サマリページを設計する。** ここが最も重要。
   - **「確認できた結果」と「効果が見込めないと確認できたもの」を並べる**
   - **棄却した仮説を隠さない。** 「調べたが効果がなさそうと分かった」は
     相手の意思決定を確実に助ける結果である
5. **各ページを2段（スライド／口頭）で書く。**
   - **見出しは結果を述べる文にする。** 解釈を含む言い切りにしない
   - 数字はそのページで示す結果だけ
   - 留保はフッターに1行、または口頭に回す
6. **口頭で必ず伝える留保を一覧にする。** 台本化を必須の宿題として明記する。
   - 母集団のカバー率 / 抽出条件の未確認 / 対照群の不在 / 外れ値の原因未特定
   - **言い忘れると後で問題になるものを漏らさない**
7. **想定質問と回答を用意する。**
   **母数・カバー率・抽出条件の質問は必ず来る。**
8. **`sources.md` を作る。** 資料上のすべての数値の出所を書く。

## 出力形式

[docs/presentations/_TEMPLATE_outline.md](../../../docs/presentations/_TEMPLATE_outline.md) と
[_TEMPLATE_sources.md](../../../docs/presentations/_TEMPLATE_sources.md) に沿って書く。

## 品質基準

- **各ページが `スライドに載せる` / `口頭で補足` に分かれている**
- **見出しが結果を述べる文になっている**（解釈の言い切りになっていない）
- **棄却した仮説がサマリに載っている**
- **口頭で伝える留保が一覧化され、どのページで言うか決まっている**
- **`sources.md` に資料上のすべての数値がある**
- 推定値にスライド上の前提の明記がある
- `検証中` の数値が混ざっていない
- 三次資料が根拠の事実記述が混ざっていない
- 個人を特定しうる値が含まれていない
