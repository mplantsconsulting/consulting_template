# notebooks — 探索の作業場（Git管理外）

**このフォルダの中身はコミットしない。**
`.gitignore` で `/notebooks/**` と `*.ipynb` を除外している（この README のみ例外）。

理由は2つある。

1. **出力セルに受領データの中身がそのまま残る。**
   `df.head()` の結果には氏名・住所・個別の識別番号が入りうる。
   ノートブックをコミットすると、[data/](../data/) をGit管理外にしている意味がなくなる。
2. **ノートブックは成果物ではない。** 実行順に依存し、途中のセルを消せば再現できなくなる。
   [scripts/README.md](../scripts/README.md) の「**再実行できない集計は結果として扱わない**」を満たせない。

> **ノートブックは「考えるための場所」であって「残すための場所」ではない。**

---

## 置くもの

- 受領データの中身を最初に眺めるための試行（列の意味の当たり、分布の確認）
- 手法・可視化の当たりを付けるための試行錯誤
- 結合キーが実際に一致するかの手探りの確認

## 置かないもの

- 分析の結果として残すもの → [scripts/](../scripts/)（分析IDと1対1）に書き直す
- 複数の分析で使い回す処理 → [src/](../src/)
- 図・集計値の最終出力 → `docs/analysis/<担当者名>/ANL-NNN_<テーマ>/`

## 命名規則

```
<担当者名>/<内容>.ipynb    例: hirose/explore_billing_columns.ipynb
```

[docs/analysis/](../docs/analysis/) [scripts/](../scripts/) と同じ担当者ディレクトリを使う。
**採番はしない。** 分析IDを付けたくなった時点で、それは `scripts/` に移すべきものである。

---

## ルール

1. **分析の結論をノートブックのまま報告しない。**
   ノートブックで見えた結果は、[docs/analysis/](../docs/analysis/) の計画（判定基準まで）を書いた上で
   `scripts/<担当者名>/ANL-NNN_*.py` に書き直してから結果として扱う。
   **「ノートブックで見えていること」は、まだ結果ではない。**
2. **共有したくなったらスクリプトに移す。** ノートブックを人に渡さない。
   渡す必要が出た時点で、それは再現性を要求される段階に入っている。
3. **共通処理をノートブックに書き溜めない。** 定義を持つ処理は [src/](../src/) に切り出す。
   ノートブック内のコピーが増えると、**同じ指標が担当者ごとに違う定義で計算される。**
4. **`data/raw/` を書き換えない。** 読み取り専用として扱う（[data/README.md](../data/README.md)）。
5. **中間データをノートブックから直接 `docs/` に書き出さない。**
   `docs/` 配下への出力は `scripts/` からのみ行う（出所を辿れる状態を保つため）。

## 起動

`ipykernel` は開発依存に入っている。VS Code / Cursor でカーネルに `.venv` を選ぶ。

```bash
uv sync
```
