# src — 共通処理

## 目的

複数の分析で使い回す処理を1か所に置き、**分析ごとに定義がブレるのを防ぐ。**

## 置くもの

- データの読み込み（文字コード・区切り・型・ヘッダー欠落の指定を含む）
- 列名・表記ゆれの正規化
- 期間・経過日数など、**定義が共有されるべき導出値の計算**
- 図の共通スタイル

## 置かないもの

- 特定の分析にしか使わない処理 → [scripts/](../scripts/) 側に書く

## ルール

1. **定義を持つ関数は、定義の出所をdocstringに書く。**
   主要な語（案件の中心となる指標や状態の定義）の計算は、
   [docs/business/](../docs/business/) の用語定義と
   [docs/data-dictionary/](../docs/data-dictionary/) の定義台帳にリンクさせる。
2. **定義を変えたら、影響する分析を洗い出す。**
   共通処理の変更は**過去の分析結果の意味を変える。**
   変更時は該当する [docs/analysis/](../docs/analysis/) の分析に更新履歴を残す。
3. **破壊的な変更を避ける。** 既存の関数の挙動を変えるより、新しい関数を足す。
4. インターフェイスは軽く実装する。**汎用性よりも検証スピードを優先する**（[CLAUDE.md](../CLAUDE.md)）。

## docstring の例

```python
def days_overdue(due_date: pd.Series, paid_date: pd.Series) -> pd.Series:
    """経過日数を計算する。

    定義: docs/business/glossary_<トピック>.md の「<用語>」に従う
        - 起点は支払期日の翌日（期日当日は0日として扱う）
        - 未入金の場合は基準日までの日数を返す

    この定義を変える場合、以下の分析の結果が変わる:
        - docs/analysis/ANL-003_xxx.md
        - docs/analysis/ANL-007_xxx.md
    """
```
